# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.

## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `PATCH /api/v1/tasks/{id}/status`
- `DELETE /api/v1/tasks/{id}`

## Реализация фичи - Периодичность задач

### Типы периодичности

| Тип | `periodicity_type` | Обязательные поля |
|---|---|---|
| Ежедневно каждые N дней | `daily` | `interval` (целое, > 0) |
| Еженедельно по дням недели | `weekly` | `weekdays` (массив, 0=вс, 1=пн, ..., 6=сб) |
| Ежемесячно по числам | `monthly` | `days` (массив чисел месяца, 1–30) |
| На конкретные даты | `spec_dates` | `dates` (массив дат YYYY-MM-DD) |
| По чётным/нечётным дням | `even_odd` | `parity` (`"even"` или `"odd"`) |

### Как работает создание задач

**`daily`, `weekly`, `monthly`, `even_odd`** — задачи создаются по цепочке. При переводе периодической задачи в статус `done` автоматически создаётся следующая задача согласно тому же правилу, что и предыдущая. Таким образом в трекере всегда есть ровно одна активная задача серии.

**`spec_dates`** — все задачи создаются сразу при создании первой. Поле `scheduled_at` игнорируется: дата первого вхождения берётся автоматически из первой (наименьшей) даты в списке `dates`. Все задачи создаются в рамках одной транзакции.

### Примеры

Ежедневно каждые 3 дня:
```json
{
  "title": "Обзвон пациентов",
  "scheduled_at": "2026-05-01T09:00:00Z",
  "is_periodicity": true,
  "repeat_rule": {
    "periodicity_type": "daily",
    "interval": 3
  }
}
```

Еженедельно по понедельникам и пятницам:
```json
{
  "title": "Еженедельный обход",
  "scheduled_at": "2026-05-04T08:00:00Z",
  "is_periodicity": true,
  "repeat_rule": {
    "periodicity_type": "weekly",
    "weekdays": [1, 5]
  }
}
```

Ежемесячно 1-го и 15-го числа:
```json
{
  "title": "Формирование отчётности",
  "scheduled_at": "2026-05-01T10:00:00Z",
  "is_periodicity": true,
  "repeat_rule": {
    "periodicity_type": "monthly",
    "days": [1, 15]
  }
}
```

По чётным дням:
```json
{
  "title": "Инвентаризация",
  "scheduled_at": "2026-05-02T09:00:00Z",
  "is_periodicity": true,
  "repeat_rule": {
    "periodicity_type": "even_odd",
    "parity": "even"
  }
}
```

На конкретные даты (`scheduled_at` не требуется — берётся из первой даты списка):
```json
{
  "title": "Плановая операция",
  "scheduled_at": "2026-05-10T08:00:00Z",
  "is_periodicity": true,
  "repeat_rule": {
    "periodicity_type": "spec_dates",
    "dates": ["2026-05-10", "2026-06-14", "2026-07-20"]
  }
}
```

### Принятые решения и допущения

**Смена статуса вынесена в отдельный эндпоинт** (`PATCH /tasks/{id}/status`). Изменение статуса — это отдельное действие, семантически не связанное с редактированием содержимого задачи. Это позволяет избежать случайного сброса статуса при обновлении полей задачи.

**Следующая задача создаётся при статусах `done` и `canceled`.** Оба статуса означают завершение текущего вхождения — задача либо выполнена, либо пропущена по обстоятельствам (врач заболел, пациент не явился). В обоих случаях серия продолжается и следующая задача создаётся автоматически.

**Прерывание серии периодических задач.** При необходимости прервать серию периодических задач, мы должны удалить текущую задачу из серии с помощью метода Delete. В таком случае серия прервется и следующая задача не будт создана.

**Время суток сохраняется при переносе на следующую дату.** Если задача запланирована на 09:00, следующая также будет на 09:00 — время берётся из `scheduled_at` исходной задачи.

**Еженедельная периодичность как дополнительный формат периодичных задач.** Помимо четырех заявленных в условии типов периодичности был реализован тип еженедельной периодичности с указанием дней недели, на которые должны быть выставлены задачи. Указаные в условии типы не покрывают распространённый медицинский сценарий, например, «каждый вторник и пятницу». Ежедневный тип с `interval=7` даёт «раз в неделю от конкретной даты», но не позволяет привязаться к дням недели. Тип `weekly` закрывает эту потребность.
